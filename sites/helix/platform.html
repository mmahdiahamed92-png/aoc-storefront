Orchestration Layer

Planners, executors, reviewers — a task graph that runs itself

Helix decomposes a spec into a DAG of discrete tasks, then assigns each node to the agent best suited for it. Planners break work down. Executors write code in parallel. Reviewers diff, test, and gate. No manual prompting between steps — the swarm self-coordinates through a shared context window and structured handoffs.

  • Planner agents decompose specs into a typed task graph with explicit dependencies and acceptance criteria
  • Executor agents pick up leaf nodes in parallel, each scoped to a single file, module, or service boundary
  • Reviewer agents run automated diffs, static analysis, and test suites before any task is marked resolved
  • Shared memory layer gives every agent live access to repo context, decisions, and prior review outcomes
How a Swarm Ships

From spec to merged PR in one continuous flow

01

Spec ingestion

Drop a ticket, PRD, or loose description. Helix parses it into structured requirements, identifies ambiguity, and asks targeted clarifying questions before committing to a plan.

02

Decomposition

The planner agent builds a task graph — breaking the feature into schema changes, API endpoints, frontend components, tests, and docs — each with explicit dependencies and definition of done.

03

Parallel build

Executor agents claim independent nodes and build simultaneously. Shared memory keeps them aligned on interfaces and conventions so the pieces compose cleanly at merge time.

04

Review and ship

Reviewer agents run diffs, tests, and lint. Everything that passes opens a PR with a full change log. Human approval gates stay in place — you merge when you're satisfied.

Engineering Questions

Answers for teams evaluating Helix

Do we own the code the agents generate?
Yes. All generated code lands in your repository under your existing license and copyright. Helix never retains ownership or injects proprietary dependencies. You can audit every change before it merges.
Which models power the agents?
Helix is model-agnostic. The orchestration layer routes tasks to the best-suited model for each job — Claude for long-context planning, GPT-4o for rapid iteration, specialized open-weight models for cost-sensitive batch work. You can pin models per project or let the router optimize automatically.
Can we run Helix on-prem or in our VPC?
Enterprise deployments support VPC isolation and on-prem orchestration runtimes. Agent execution, memory, and secrets stay inside your network perimeter. We support AWS, GCP, and Azure with Terraform modules for fast provisioning.
How does Helix integrate with our existing repos and CI?
Helix connects via standard Git providers — GitHub, GitLab, Bitbucket — and reads your existing CI config to understand build, test, and deploy steps. Agents open branches and PRs through your normal workflow. Your CI pipelines run unmodified; Helix simply reacts to their results.
